# ERPNext / Frappe v15 — Performance Testing App Guide

**Purpose:** Build (or port) a Locust-based concurrent desk-mix load test app for **Frappe v15 / ERPNext v15**, based on the existing v16 `performance_testing` app.

This document is the v15 counterpart to the v16 work. Locust still runs as a **client** (local or separate machine). The Frappe app on the target site is mainly for **seeding** test users and masters.

---

## 1. Goal

Answer:

> Can ERPNext **v15** handle ~100 concurrent Desk-like users (realistic mix of sales, purchase, stock, accounts, manufacturing, reports) with acceptable latency and error rate?

Same Phase 19 desk mix as v16:

| Persona | % | Users @100 |
|---|---:|---:|
| Sales | 25% | 25 |
| Purchase | 15% | 15 |
| Stock | 15% | 15 |
| Accounts | 20% | 20 |
| Manufacturing | 10% | 10 |
| Report / Manager | 15% | 15 |

Think time: 3–8 seconds. Read ~60% / write ~40%.

---

## 2. Recommended approach

**Do not** try to run one app branch on both v15 and v16.

| Bench | App branch | Notes |
|---|---|---|
| Frappe/ERPNext **v16** | `version-16` | Current app |
| Frappe/ERPNext **v15** | `version-15` | New / ported app |

Options:

1. **Clone + port** this repo to branch `version-15` and adjust files below  
2. **`bench new-app performance_testing`** on a v15 bench, then copy `loadtest/`, `locustfile.py`, `setup/seed_loadtest.py`, scripts, and this guide

## 5. Port checklist (v16 → v15)

### 5.1 `pyproject.toml`

Change Python target for v15 benches:

```toml
requires-python = ">=3.10"
# optional comment:
# "frappe~=15.0.0"  # managed by bench
```

Ruff (if used):

```toml
target-version = "py310"
```

### 5.2 Git branch

```bash
git checkout -b version-15
# or: bench get-app <url> --branch version-15
```

### 5.3 Seed script — company and masters

In `seed_loadtest.py`:

- Set `COMPANY` to the **real company name** on the v15 site (do not assume `Fusion`).
- Confirm these exist or adjust names:
  - Customer Group (non-group, e.g. `Commercial`)
  - Territory
  - Supplier Group + `supplier_type`
  - Item Group (e.g. `Products`)
  - UOM `Nos`
  - Warehouse used in Locust writes (e.g. `Stores - X`)
- Keep `frappe.flags.in_import = True` before creating 100 users (avoids User creation throttle).

### 5.4 Roles (v15)

Most roles match ERPNext v15. Verify on the site:

```text
Sales User, Purchase User, Stock User, Stock Manager
Accounts User, Accounts Manager
Manufacturing User
Sales Manager, Purchase Manager
Desk User
```

If a role is missing, either create it in seed (`_ensure_role`) or map to the closest v15 role.

### 5.5 Desk / API endpoints (usually unchanged)

Locust should still use:

```text
GET  /api/method/frappe.auth.get_logged_user     # token check / login metric
GET  /api/resource/<Doctype>                    # list
GET  /api/method/frappe.desk.form.load.getdoc
POST /api/method/frappe.desk.form.save.savedocs
POST /api/method/frappe.desk.query_report.run
Header: Host: <site-name>
Header: Authorization: token <api_key>:<api_secret>
```

If a report fails on v15, fix **filters** in `personas.py` (P&L / Trial Balance filters often differ by version). Prefer POST for `query_report.run`.

### 5.6 Naming series

Sales Order / Purchase Order / Stock Entry / Journal Entry series strings can differ by company setup. If save fails with naming series errors, read the site’s default series and update `personas.py`.

### 5.7 Locust install (not via bench install-app)

```bash
./env/bin/pip install -r apps/performance_testing/requirements-loadtest.txt
```

Installing the Frappe app does **not** install Locust.

## 6. Install on a v15 bench

```bash
cd /path/to/frappe-bench-v15

# App
bench get-app /path/or/url/to/performance_testing --branch version-15
bench --site <site> install-app performance_testing

# Locust (bench env)
./env/bin/pip install -r apps/performance_testing/requirements-loadtest.txt

# Seed users + masters + users.json
bench --site <site> execute performance_testing.setup.seed_loadtest.seed
# or console:
#   from performance_testing.setup.seed_loadtest import seed
#   seed()
```

Confirm seed output path:

```text
apps/performance_testing/loadtest/users.json
```

## 7. Run Locust against local v15 site

```bash
# Terminal 1
bench start

# Terminal 2
cd apps/performance_testing
export PERF_SITE_HOST=<site-name>
export PERF_COMPANY=<Company Name>
export PERF_FISCAL_YEAR=<Fiscal Year name>   # e.g. 2025-2026
../../env/bin/locust -f locustfile.py --host http://127.0.0.1:<web-port>
```

UI: http://localhost:8089  

Start with **10 users**, spawn rate **2**, then ramp toward **100**.

Headless ramp:

```bash
./scripts/run_ramp.sh
```

Update `PERF_BASE_URL` / host in the script or env for the v15 port.

## 8. Remote v15 server (Locust on laptop)

```text
Remote v15 site
  → install performance_testing (version-15)
  → run seed
  → copy users.json to laptop

Laptop
  → pip install Locust (or use local bench env)
  → locust --host https://remote-erp.example.com
  → PERF_SITE_HOST=<remote-site-name>
```

Locust does **not** need to run on the remote server. The remote site **does** need the seeded users (app recommended for seed).

## 10. Pass / fail SLOs (same as v16 Stage 1 bar)

| Metric | Pass |
|---|---|
| Error rate (5xx / Desk errors) | &lt; 1% |
| Login P95 | &lt; 3s |
| List / form open P95 | &lt; 2s |
| Save P95 | &lt; 3s |
| Submit P95 | &lt; 5s |
| Report P95 (one company/period) | &lt; 10s |

If 50 users pass but 100 fail, record **max sustainable concurrent users** — valid PoC result.

---

## 11. What not to expect from v15 vs v16 comparison

- Same Locust mix does **not** mean identical numbers: different Python, workers, data, hardware, and product code.
- Compare only when hardware and data stage are documented.
- Always label: `v15 bench baseline` vs `v16 bench baseline`.

---

## 12. First tasks on a clean v15 site

1. Create / use a dedicated test site.  
2. Install ERPNext v15 + `performance_testing` (`version-15`).  
3. Set `COMPANY` (and warehouse/series) in seed + config.  
4. Run seed → confirm 100 users and `users.json`.  
5. Install Locust in the bench env.  
6. Smoke: Locust **5 users × 2–5 minutes**.  
7. Ramp: 10 → 25 → 50 → 100; fill results table.  

Do **not** start at millions of rows. Concurrent desk mix first; scale data later.

## Final principle

The v15 app answers the same question as v16:

> Can this ERPNext version serve ~100 concurrent realistic Desk users with acceptable performance and integrity?

Use a dedicated `version-15` app/branch, seed on the target site, run Locust from any machine that can reach that site.
